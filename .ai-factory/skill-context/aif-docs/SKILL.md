## Rules

### Write Persisted Artifacts in English
**Source**: codebase convention
**Rule**: All documentation, specs, plans, ADRs, READMEs, session/deferred entries, code-facing prose, commits, and PR text are English. Chat may follow the user's language.

### Translate Meaning Without Mixing Exposition
**Source**: codebase convention
**Rule**: Translate non-English user statements into English meaning rather than pasting foreign-language quotations into English exposition. Non-English text is allowed only when it is the corpus/fixture/i18n/domain subject, with an English gloss where needed.

### Maintain the Standards Index
**Source**: codebase convention
**Rule**: `docs/standards/README.md` links to authoritative standards and must be updated in the same change when a standard is added or retired. Do not duplicate full standard content into the index or unrelated docs.

### Maintain Session Continuity
**Source**: codebase convention
**Rule**: Update the `▶ NEXT SESSION` block in the correct `SESSION_HANDOFF.md` at meaningful phase boundaries and with substantive commits; keep it concise, current, and clear stale/closed deferrals.

### Keep Documentation Scoped
**Source**: codebase convention
**Rule**: Read and update only the active module's documentation plus applicable cross-cutting sources; do not expand docs with stale service inventories or duplicate ownership maps.

### Preserve the Established Documentation Taxonomy
**Source**: `docs/` convention
**Rule**: Use `.ai-factory/references/project-docs-map.md` to route changes. Do not reorganize the repository's large `docs/` tree into the generic AI Factory docs template, rename dated plans/specs, or add boilerplate navigation to every page. Make targeted edits within the existing indexes, track boundaries, ownership, and history conventions.

### Treat Status Metadata as Governance, Not Proof
**Source**: `docs/` convention
**Rule**: Preserve the distinction between planned, approved, implemented, verified, shipped, and deferred. Validate implementation claims against code, contracts, tests, Git, or runtime evidence before updating current-state documentation.

### Keep Historical Records Historical
**Source**: `docs/` convention
**Rule**: Correct current authoritative indexes, handoffs, standards, and ownership maps when necessary; do not rewrite old plans, audits, reviews, or research to make history appear current. Link to superseding material where clarification is required.
