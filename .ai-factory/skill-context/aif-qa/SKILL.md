## Rules

### Plan Boundary Evidence
**Source**: codebase convention
**Rule**: A test plan spanning two or more services must include a real stack-up cross-service smoke in addition to unit/contract tests, with explicit fallback wording only when live infrastructure is genuinely unavailable.

### Plan Safe Database Tests
**Source**: codebase convention
**Rule**: Any destructive DB scenario must specify a dedicated test DSN, a throwaway-name marker, a runtime guard before destructive SQL, owner-scoped cleanup, and no production-URL fallback.

### Plan Python Parallelization
**Source**: codebase convention
**Rule**: Full Python suites use pytest-xdist with `--dist loadgroup`; DB/port test files must be grouped to prevent interleaving. Focused iteration may be serial.

### Plan Effect-Level UI Tests
**Source**: codebase convention
**Rule**: Agent/frontend tool cases must assert the actual browser/UI effect and resolver error behavior, not only tool-call serialization or raw streaming output.

### Use Repository Test Resolvers
**Source**: codebase convention
**Rule**: Reference the repository-defined browser test account without copying credentials into QA artifacts. Resolve model IDs through `scripts/dev-model.py` and require explicit `model_ref`; never hardcode machine-local IDs or permit silent paid fallback.

### Target the Correct Frontend Runtime
**Source**: codebase convention
**Rule**: State whether the test uses the baked nginx frontend or an explicit Vite development instance; include rebuild/freshness verification so a stale or shadowing frontend cannot produce false evidence.
