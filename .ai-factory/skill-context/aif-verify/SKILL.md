## Rules

### Enforce Non-Vacuity Mechanically
**Source**: codebase convention
**Rule**: For every new or changed gate, lint, validator, assertion, or constraining test, break the real guarded subject, observe the intended failure, restore it, rerun green, and include actual red/green output in VERIFY evidence. Check variable subject, future-file scope, adjacent decisions, and reachable escape-hatch reasons.

### Require Fresh Complete Output
**Source**: codebase convention
**Rule**: Run the command, read its complete output, confirm it matches the claim, and only then report success. Cached results, "should pass", and tool start-up without exercising behavior are not evidence.

### Live-Smoke Cross-Service Changes
**Source**: codebase convention
**Rule**: When two or more services change, add real cross-service evidence using `live smoke: <evidence>`, or record `LIVE-SMOKE deferred to D-...`, or state `live infra unavailable: <reason>`; mock-only suites are insufficient.

### Verify Frontend Tools by Effect
**Source**: codebase convention
**Rule**: For agent-to-GUI tools, verify contract snapshots on both sides and perform a live browser effect check. A correct raw tool stream with no visible/resolver effect is a failure.

### Run Python Suites Safely in Parallel
**Source**: codebase convention
**Rule**: Use `python -m pytest tests -q -n auto --dist loadgroup` for full Python VERIFY. Any test using a real DB or fixed port must declare `pytest.mark.xdist_group("pg")`; focused BUILD subsets may run serially.

### Guard Destructive Database Tests
**Source**: codebase convention
**Rule**: Destructive test setup must use a dedicated `*_TEST_*_URL`, a throwaway database name containing a test/smoke/audit marker, a runtime throwaway guard before destruction, and owner-scoped cleanup. Never fall back to a production DSN or use bare DELETE/TRUNCATE/DROP against shared data.

### Verify the Built Frontend Surface
**Source**: codebase convention
**Rule**: Remember that port 5174 serves a baked nginx build and host Vite can shadow it. For robust frontend smoke, rebuild/use the image on a free port or use the explicit Vite development port documented by the repository, then verify relative `/v1` routing through the gateway.

### Resolve Test Models Dynamically
**Source**: codebase convention
**Rule**: Use `scripts/dev-model.py` for the required capability and pass an explicit `model_ref`; never hardcode a machine-specific user-model ID or silently choose a billed fallback.

### Verify Documentation Claims Against Implementation Truth
**Source**: `docs/` convention
**Rule**: Use `.ai-factory/references/project-docs-map.md` to locate acceptance claims, but prove them with current code, machine contracts, tests, gates, Git, and runtime evidence. Approval labels, readiness `GO`, checked plan boxes, and file presence are not completion evidence.

### Report Drift Separately From Product Failure
**Source**: `docs/` convention
**Rule**: Distinguish an incorrect or stale documentation claim from an implementation defect. Name the authoritative source that should be corrected and avoid rewriting historical plans or audit records merely because their status is old.

### Verify the Governing Slice, Not the Entire Archive
**Source**: `docs/` convention
**Rule**: Resolve the current plan/spec through the handoff, user selection, or run-state; load only its applicable standards, ownership maps, and QA evidence. Do not let unrelated historical plans or the separate MMO-RPG design tree redefine acceptance criteria.
