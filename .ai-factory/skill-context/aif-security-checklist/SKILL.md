## Rules

### Audit Tenant Scope First
**Source**: codebase convention
**Rule**: Verify every user-facing table, query, uniqueness constraint, cache key, and write endpoint has an explicit System, Per-user, or Per-book/project scope and cannot let one tenant affect another without a grant.

### Protect System-Tier Data
**Source**: codebase convention
**Rule**: Regular users may read but never mutate System-tier defaults. User customization must clone or override into user/book scope; System writes require an admin-only surface.

### Centralize Provider Secrets
**Source**: codebase convention
**Rule**: Provider credentials and SDK/API access exist only in `provider-registry-service`; local backends are registered as BYOK credentials, not consuming-service URL/token environment variables.

### Keep Secrets Out of Tracked Artifacts
**Source**: codebase convention
**Rule**: Secrets come from ignored local environment or deployment secret stores and required services fail closed when absent. Scan staged diffs and logs for credential values, and never copy repository test credentials into AI Factory context.

### Secure External Agent Capabilities
**Source**: codebase convention
**Rule**: Imported skills/plugins/MCP registrations require quarantine, prompt-injection scanning, SSRF controls, validation parity across import paths, degrade-safe resolution, and a live end-to-end consumer proof before advertisement.

### Protect Databases From Tests
**Source**: codebase convention
**Rule**: Block unscoped destructive test SQL, production DSN fallback, non-throwaway DB names, and destruction before a runtime throwaway guard. Require scoped cleanup even in a disposable database.

### Review Load-Bearing Surfaces Adversarially
**Source**: codebase convention
**Rule**: Recommend the repository's deep implementation review at POST-REVIEW for auth/credentials, tenant isolation, destructive operations, injection defenses, and new service boundaries; require fresh verification after fixes.
