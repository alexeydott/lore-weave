# Resume control missing for failed EPUB imports in generic Jobs

**Date:** 2026-08-04 20:15
**Files:** services/jobs-service/app/contract.py, services/jobs-service/app/control.py, services/jobs-service/tests/test_control_caps.py, services/jobs-service/tests/test_control.py, services/book-service/internal/api/server.go, services/book-service/internal/api/epub_import_job_status.go, services/book-service/internal/api/epub_import_recovery_db_test.go
**Severity:** medium

## Problem

The generic `/jobs/book/{job_id}` view rendered no Resume action for a failed
EPUB Book import, even though the authenticated EPUB API could resume the same
durable job.

## Root Cause

The Jobs projection deliberately classified `book_import` as view-only and did
not register Book Service in its internal control-forwarding registry. The
generic UI correctly renders only producer-supplied control capabilities, so it
had no safe route to expose.

## Solution

Book imports now advertise Resume only while failed or cancelled. Jobs Service
forwards that action to a Book internal endpoint. Book Service rechecks the
durable job owner before reusing the existing resume transaction, so a stale
projection cannot act across tenants. The internal path emits a structured
`[FIX]` success log without source content.

## Prevention

- When an owner service adds a public recovery action, add the corresponding
  generic Jobs capability and internal forwarding seam together.
- Keep the UI capability test and the owner-revalidation DB test paired: one
  proves visibility and routing, the other proves tenant safety.
