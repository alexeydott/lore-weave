# PostgreSQL connection headroom in Docker Compose

**Date:** 2026-08-03 02:31
**Files:** infra/docker-compose.yml
**Severity:** medium

## Problem

The local Docker Compose stack exhausted PostgreSQL's default 100 connection
slots during a cold start. `roleplay-service` could not acquire a connection
for startup migrations and exhausted its five configured restart attempts.

## Root Cause

The default Compose PostgreSQL service did not set `max_connections`, despite
the local stack running 22 per-service databases. Its steady-state pools used
about 90 client connections, leaving insufficient headroom for concurrent
service initialization.

## Solution

Configured the PostgreSQL container with `-c max_connections=300`, matching
the existing scale-stack connection ceiling and providing 297 application
slots after the PostgreSQL superuser reserve.

## Prevention

- Keep the default Compose connection limit aligned with the number and pool
  sizes of locally started services.
- Check `pg_settings.max_connections` and `pg_stat_activity` after adding a
  database-backed service or changing pool limits.
- Verify that Compose parses the server command and that PostgreSQL reports
  the expected command-line setting at runtime.
